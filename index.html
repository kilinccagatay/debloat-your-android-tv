01 / PURPOSE

What this guide does

Factory Android TV software varies by brand, model and firmware. A package that is unnecessary on one television may provide inputs, remote buttons, audio, DRM or updates on another. This guide therefore avoids universal debloat lists.

Instead, it gives an AI coding agent a disciplined procedure: inventory the real device, take baseline measurements, research uncertain components, ask before acting and keep every package change reversible.

04 / PROJECTIVY

Verify the replacement before touching the original

Projectivy provides a clean, customizable Android TV Home experience with app categories and shortcuts to supported inputs. Some visual customization features require its premium upgrade; the core workflow in this guide does not assume that every feature is free.

Install it from Google Play or another trustworthy official distribution route. Open it, launch apps, test Inputs and confirm that the Home button reaches it. Only then should the stock launcher become a candidate for reversible disabling.

The optional accessibility service can enable custom remote-control actions. Read the permission explanation and decide whether those functions are useful; the cleanup itself should not depend on blindly granting access.

05 / SAFETY RULES

Rules that stop a cleanup becoming a repair job

Never classify by name alone

Research package identity and behavior. Brand firmware often hides essential functions behind unclear package names.

Protect the TV's fundamentals

Preserve inputs, HDMI, remote control, audio, Wi-Fi, the active keyboard, Play services, Play Store, DRM, System UI and recovery/update components.

Change no more than ten

Use small, approved batches and test Home, Inputs, remote buttons, sound, keyboard, networking and core streaming apps after each batch.

Do not confuse motion with speed

Animation scales at 0.5 can make transitions feel quicker, but they do not upgrade the CPU, memory or storage.

Not part of this guide

No root access, bootloader unlocking, firmware flashing, factory reset, indiscriminate cache clearing or deletion of user data.

What one older Philips TV showed

These are observations from one Philips 43PUS8007/12 running Android TV 14—not expected results for other devices.

The weak CPU cores and limited memory were the main constraints. Storage capacity and sequential throughput did not appear to be the primary bottleneck, and no clear thermal throttling was observed. Android Studio screen mirroring created substantial software-encoding and compositor load, so it was excluded from meaningful performance measurements.

07 / ROLLBACK

Keep the way back beside every change

For every disabled package, record the package name, reason, test result and the exact enable command. If something breaks, stop changing the TV and restore the newest batch first.

adb shell pm enable <package>

A machine-readable disabled-packages.txt and a human-readable change log turn recovery into a known procedure instead of a memory test.
